# WebOS Chromium CI (test)

Builds [WebOS Chromium](https://github.com/sarahahzub/WebOS-Chromium) from its published `source/` on GitHub-hosted
runners, so anyone can see how an IPK was made. This repo is the test bed; once the workflow is proven, it moves into
the main repo.

## What a run does

Start **Actions → Build WebOS Chromium → Run workflow** (inputs: source repo, branch or commit, IPK version,
variants). The branch is resolved to one commit at the start, and every job builds that commit.

| Job | What | Script from `source/` |
|---|---|---|
| Source commit | resolves the branch to a commit | |
| Chromium source | chromium151 at the pinned commit, Chromium's clang, Rust and node | `container/setup-source.sh` |
| Sysroot and builtins | the public sysroot (Ubuntu packages + stub libraries, no TV files), glibc 2.24, compiler-rt | `container/build-sysroot.sh`, `build-sysroot-compat.sh`, `build-builtins.sh` |
| NSS and NSPR | from the Mozilla tarballs with the openlgtv SDK | `container/build-nss-sdk.sh` |
| Launcher | `bin/run` | `package/launcher/build.sh` |
| Build part 1, 2, ... | the browser, about 5 hours per job (a hosted job stops at 6 hours); each part continues the previous one's build folder | `container/build.sh` |
| IPK and provenance | the IPK, plus a signed build provenance attestation | `package/mkipk.py` |
| Result | the end summary (both IPKs, sha256, how to verify); one logs artifact; deletes the hand-overs between jobs | |

Source, sysroot and NSS are cached, so later runs of the same Chromium commit skip those jobs. The container
(`ci/Dockerfile`) has the same contents as the Modal image in `source/modalapp/build.py`.

## Variants

| Variant | args.gn | App |
|---|---|---|
| default | as in `source/args.gn` (ARMv7, every TV from webOS 4.4) | `io.github.sarahahzub.chromium` |
| armv8 | `arm_arch = "armv8-a"`, `arm_version = 8` (patch 0056: ARMv8 FPU, Cortex-A55 tuning) | `io.github.sarahahzub.chromium.armv8`, installs next to the normal app |

Both variants also set `cc_wrapper = ""`: no ccache, because the build folder itself carries the state between jobs.
`ci/prep-cn.sh` makes these changes in a copy and prints the diff in the log. Nothing else in `source/` changes.

## What a finished run keeps

Three artifacts:
- **webos-chromium-default**: the default IPK.
- **webos-chromium-armv8**: the ARMv8 IPK.
- **logs**: everything else: the build logs of every job, `SHA256SUMS` (the IPK and the browser it holds), the ABI
  and NSS reports, and the launcher. The browser itself is only inside the IPK.

The run's page has two summaries: what is being built (at the start) and the result (both IPKs with their sha256).

## Checking an IPK

Each IPK has a build provenance attestation: who built it (this workflow), from which commit, in which run.

```
gh attestation verify io.github.sarahahzub.chromium_1.0.0_arm.ipk -R sarahahzub/webos-chromium-ci
```

It proves where the file was built, not that a rebuild gives the same bytes.

## Files

- `.github/workflows/build.yml`: the whole run.
- `.github/workflows/variant.yml`: one variant's chain of build jobs. Generated by `ci/gen-variant-workflow.py`.
- `.github/actions/prepare`: checkout, disk space, swap, container image, cache keys.
- `ci/`: the container, host setup, the variant's args.gn, status between parts, packaging.
